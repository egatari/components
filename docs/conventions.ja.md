## 1. 見せ方の種類

### 1.1 何のためか

同じパーツがいつも同じ見せ方で出ると、資料がどれも同じに見えて飽きる（数字の札がいつも数え上げる）。そこでパーツごとに見せ方を何種類か持つ。最初の見せ方が既定で、作者（または資料を書く AI）が `variant` で名前を書けばほかの見せ方になる。資料のシード値はもうない：egatari-spec 28d8801 までは資料の `data-egatari-seed` で選んでいたが、Studio はもう書かない（仕様 §8.4）。

### 1.2 見せ方が変えてよいもの、変えてはいけないもの

見せ方が変えてよいのは、ステップの中で**どう現れるか、どこに目を向けさせるか**だけ。

| 変えてよい | 変えてはいけない |
|---|---|
| 現れ方（フェード・下から・桁ごと・線を引く など） | ステップの数（`steps`） |
| ステップの中の動きの順（左から／大きい順 など） | ステップの長さ（`duration(k)`）と合図（`cues(k)`） |
| 注目の印（下線・枠）の有無 | 最後の状態（`t = Infinity`）が伝える中身：字・数・位置・色の意味 |
| | 使う色（テーマの変数だけ） |
| | 動きの量の上限（長さ・距離・回数を、見せ方 0 より大きくしない） |

ステップの数と長さと合図を変えないので、台本・動画の時間・字幕・先のステップを薄く見せる表示・印刷・読み上げは、見せ方によらず同じになる。

- **動きは注目を導くためだけに使う。** 跳ね続ける、回り続ける、揺れ続けるなどの飾りの動きは入れない。どの見せ方も、ステップの中で動き終わって止まる。
- **動きを減らす設定（`prefers-reduced-motion`）は、どの見せ方でも守られる。** 実行系がこの設定のときは `t = Infinity` で描く（`kit/deck.js`）。なので、どの見せ方でも最後の状態だけで読めること。最後の状態に注目の印（下線など）が残る見せ方は、止まった絵でも意味が通る印に限る（「この数字が大事」を表す下線はよい。動いていないと分からない印はだめ）。
- **先のステップを薄く見せる表示**（先のステップも見せる表示。仕様 §8.4 で `ctx.preview === true` という旗になった。`ctx.mode` は "talk" | "learn" | "video"）。パーツは `ctx.preview || ctx.mode === "lecture"` で調べる（今の同梱の実行系は `ctx.mode === "lecture"` を渡し、次の実行系は `ctx.preview` を渡すので、どちらでも動く）。先のステップを薄く見せる表示では（仕様 §8.4「Answers under preview」、Player P1）：
  - **どのパーツも先を見せる**：後のステップで足される中身を、最後の形のまま（動かさずに）テーマの `--preview-opacity` の濃さで描く。見せ方によらず同じ。値は要素で読む（`parseFloat(getComputedStyle(this).getPropertyValue("--preview-opacity"))`）。0.45 はこの変数がないときだけの代わりで、値を書き込まない。変わるものをこれより濃く描かない。
  - 今のステップはふだんどおりに描く。前のステップは出来上がっている。ステップ 0 からもともと見えている中身は変えない。
  - 薄く見せている中身の操作は効かない（押せない・選べない。m-menu の先の札）。
  - **例外のパーツ**は、先のステップが、学習者が先に考えるべき答えであるもの：index.js に `static preview = "none";` と書き、先を何も見せない（先のステップを薄く見せる表示でない時とまったく同じに描く）。`tools/lint.mjs` がこの旗を読み（値は `"none"` だけ）、`tools/release.mjs` が manifest.json の `components.<名前>.preview: "none"` に書く（`interactive`・`group`・`tile` と同じ）。今の例外：`m-predict`（答え）、`m-hissan`（数字が計算そのもの）、`m-timer`（先の時間は中身ではない）、`m-orbit`（先の形は、学習者が予想するもの）。
  - 例外ではないもの：`m-kanbun` の読む順と `m-kobun` の品詞も、ほかと同じく先を見せる。特定の答え（練習問題、ある読む順）を隠したいときは、作る人が要素に `data-preview="none"` を付け、実行系がそれを隠す。パーツはそのために何もしない。
  - `tools/test-preview.mjs` が、どの見本も `ctx.preview` あり・なしで描く：先を見せるパーツはステップ 0 でより多くを `--preview-opacity` の濃さで描く。例外のパーツはまったく同じに描く。どのパーツもどちらかである。
- **最初の見せ方（見せ方 0、既定）** は、今あるパーツでは今の見せ方そのもの。新しいパーツでは、いちばん控えめな見せ方（フェードして現れる）。

### 1.3 属性

| 置き場所 | 書き方 | 意味 |
|---|---|---|
| パーツ | `variant="名前"` | 見せ方を名前で選ぶ（人が「数え上げで」と言ったときなど）。書かなければ最初の見せ方 |

- `variant` に知らない名前が書いてあれば、警告（`console.warn`）を出して最初の見せ方にする。
- `variant` はどのパーツにも共通の属性で、`static props` には書かない。
- パーツの `seed="N"` と資料の `data-egatari-seed` はもう読まない（警告も出さない）。まだ書いてある資料も、名前を書いていなければ最初の見せ方になる。

### 1.4 選び方

パーツは見せ方の名前の並びを宣言する。最初が既定（見せ方 0）。

```js
static variants = ["count", "rise", "flip", "underline"];
```

README の frontmatter にも同じ並びを書く（`variants: count, rise, flip, underline`。CATALOG.md に載る）。README の本文では、最初が既定であることを短く書く（「書かなければ最初の見せ方」）。

1. パーツの `variant` 属性が見せ方の名前なら、その見せ方。
2. そうでなければ最初の見せ方。

この選び方から、次のことが言える。

- `variant` を書かないパーツは、どの資料でも同じ見せ方になる。資料ごとに変えたいときは見せ方の名前を書く。
- **最初より後ろに見せ方を足しても、資料の見た目は変わらない。** 最初の見せ方は一度出したら差し替えず、並びの先頭から動かさない。出した見せ方の名前は変えない（資料が名前で書くので）。最初でない見せ方をやめると、その名前を書いた資料だけが変わる（警告を出して最初の見せ方になる）。
- 見せ方の中で揺らぎが要るとき（札の出る順を混ぜるなど）は、データと属性から決める。`Math.random` は使わない（今までどおり）。

### 1.5 パーツが見せ方を読む方法

選び方の小さな関数を `tools/variant.js` に置き、`tools/expr.js` と同じ仕組みで使うパーツに写す（`node tools/variant-sync.mjs`、印の付いた区画を上書きする。試験が写し忘れを見つける）。パーツの中では次のように読む。

```js
// mount の中で 1 回
this.variant = VARIANT.of(this);   // "count" | "rise" | …
```

`VARIANT.of` はパーツの `static variants` を `customElements.get(タグ名)` から読み（パーツのコードに `.constructor` は書けない）、`variant` 属性を読んで、1.4 のとおりに選ぶ。`tools/test-variant.mjs` が見せ方のあるすべてのパーツで確かめる。

Studio のパーツの基底クラス（`DECK.MotionElement`）に同じものを持たせる案もある（`this.variant`）。そうなれば写した関数は要らなくなるが、Studio の変更なので dev と相談する（v0.4.8 の後）。それまではパーツライブラリの中だけで完結させる。

### 1.6 今あるパーツに見せ方を足すとき

- **最初の見せ方の描画は 1 画素も変えない。** 見せ方の名前を書いていない資料（今あるすべての資料。古いシード値があってもなくても）は、見た目が変わらない。`tools/test-default-variant.mjs` が、各パーツの demo のスクリーンショット（ステップの途中と最後）を前の版のものと比べる。名前を書いた見本のスライドも比べる。例外は先生が認めた 1 つだけ：v2.2.0（base 1.1.0 の字の幅の見積もりと 24px 以上の下付き・上付き）はすべてのパーツの配置を動かすので、それより前の版とは最初の見せ方の名前だけを比べる。
- シード値をやめても、シード値の無い資料は何も変わらない（シード値 0 はいつも最初の見せ方だった）。0 でない `data-egatari-seed`（や `seed` 属性）を書いた資料は、v1.10.0 以前に固定していれば見た目はそのまま。新しい版に移すと、名前を書いていないパーツは最初の見せ方になる。
- 資料はパーツの版を固定している（仕様 [§6](https://github.com/egatari/egatari-spec/blob/main/egatari-1.0.md#6-components-and-profiles)）。なので、資料の見た目が変わるのは、作者がパーツの新しい版に移したときだけ。見せ方を足すのは minor 版とし、CHANGELOG に書く。
- `static props` で今ある属性と見せ方が重なるときは、属性を優先する。例：`m-kpi` の `count="false"` は今までどおり「数えない」。数えることが前提の見せ方（`count`・`flip`）が選ばれていても、数えない見せ方（`rise`）にし、なぜ見せ方が変わったかを `console.info` で 1 回だけ知らせる。

### 1.7 例：`m-kpi`

| 見せ方 | ステップの中の動き | 最後の状態 |
|---|---|---|
| `count`（0、今の見せ方） | 札が下から 14 px 上がりながら現れ、数字が `from` から最後の値まで数え上がる（初めに速く、終わりにゆっくり）。増減の行は数え終わる少し前に現れる | 数字・名前・増減・一言 |
| `rise` | 数字は初めから最後の値。札が下から上がりながら現れ、数字だけ少し小さい大きさ（0.85 倍）から元の大きさに戻る | 同じ |
| `flip` | 札が現れたあと、数字が右の桁から左の桁へ 1 桁ずつ、0 から最後の数字まで縦にめくれて止まる | 同じ |
| `underline` | 札が現れ、数字が初めから最後の値で出たあと、数字の下に `--term` の線を左から右へ引く | 同じ＋数字の下の線 |

どれもステップの長さは今と同じ（`at + dur`、増減があれば ＋0.4 秒）で、合図（`cues`）も同じ。動きを減らす設定のときは、どれも最後の状態がそのまま出る。

## 2. 箱と線の図（年表・循環・木・原因と結果）

### 2.1 方針：座標を書かせない

`m-flow` は箱の座標（px）を書くパーツで、図の形を手で決めたいときにはよい。しかし AI が書くと、重なり・はみ出し・ずれが起きやすい。新しい 4 つ（`m-timeline` `m-cycle` `m-tree` `m-fishbone`）は、**中身とつながりだけを書き、並べ方はパーツが決める**。

`m-flow` はそのまま残す（座標を書く図のため）。新しい 4 つは、箱と線の欄の名前を `m-flow` とそろえる。

### 2.2 データの形

子の JSON はどれも `{"nodes": [...], "edges": [...]}` の形。`edges` は省ける。

**箱（node）の共通の欄**（`m-flow` と同じ名前）：

| 欄 | 意味 |
|---|---|
| `id` | 文字か整数。つながりを書くときに使う |
| `label` | 箱の字（短く。`\n` で改行。`*斜体*` `_下付き` `^上付き` は `m-flow` と同じ）。または `tex`（KaTeX） |
| `note` | 補足の字（`--muted`）。箱の下か、箱の中の最後の行か（線とぶつからない方）はパーツが決めて README に書く（年表・循環は中、木・特性要因図は下） |
| `tone` | `term`（既定）・`emph`・`muted`・`accent2`・`series-1..4` |
| `step` | その箱が出るステップ（書かなければ 2.4 の既定） |
| `at` | ステップの中の開始秒 |

**パーツごとの欄**：

| パーツ | 欄 | 意味 |
|---|---|---|
| `m-timeline` | `when`、`end`、`whenLabel` | 時点（数か `"1868"` `"2026-10"` `"2026-10-24"` の形の字）。`end` があれば期間（帯で描く）。**`end` は含まない**（終わりの時点。`"1912"` は 1912 年の初め）ので、明治 1868–1912 と大正 1912–1926 は同じ段に並ぶ。12 月まで含めるなら次の月（`"2027-01"`）を書く。`whenLabel` は表示する日付の字（`明治元年` など）。位置は `when` で決まる |
| `m-cycle` | （並びの順） | 並べた順に回る。最後から最初へ戻る矢印は自動で引く |
| `m-tree` | `parent` | 親の `id`。`parent` の無い箱が根（1 つだけ） |
| `m-tree` | `branch`、最上位の `path` `pathStep` `pathNote` | `branch`：親からの線に添える字（確率・条件・はい/いいえ）。`path`：根から親子の線に沿う `id` の列。木の後に線 1 本ずつ（`pathStep` があればそのステップにまとめて）`--emph` で示す。`pathNote` は終わりの箱の外に出る |
| `m-fishbone` | `parent` | 親の `id`。`parent` の無い箱が大きな骨（分類：人・機械・方法・材料 など）、その子が原因、孫が細かい原因（3 段まで）。結果（頭）は `{"effect": {"label": …}}` で別に書く |

**線（edge）**：並び・親子から決まる線は自動で引くので書かない。`edges` に書くのは、それ以外のつながり（木の枝をまたぐ関係、原因どうしの関係など）だけで、欄は `m-flow` と同じ（`from` `to` `label` `tone` `dash` `step`）。既定は破線。

例（年表）：

```json
{"nodes": [
  {"id": "a", "label": "明治維新", "when": "1868"},
  {"id": "b", "label": "大日本帝国憲法", "when": "1889", "note": "発布"},
  {"id": "c", "label": "日清戦争", "when": "1894", "end": "1895", "tone": "emph"}
]}
```

### 2.3 並べ方の決まり

- **要素の箱の中に収める。** 字の大きさは要素の大きさから決め、収まらなければ小さくする。下限は 24 px（Studio の品質チェックが図の中の字に求める大きさ。本文は 27 px）。下限より小さくはせず、下限でも収まらないときは `ctx.report("size", …)` で知らせる（Studio の品質チェックに出る。試験もこれを見る）。わざと小さくする字（補足・目盛りの字）には `data-annot` を付ける（`m-kanbun` と同じ。品質チェックの `smallSvgText` はこれを除く）。
- 箱の幅は字数から見積もる（`m-kpi` と同じ。字の読み込みを待たない）。箱どうし、字と線は 4 px より近づけない（`tools/test-components.mjs` が見る。`m-flow` と同じ）。
- 向きは `orient` 属性：`m-timeline` は `h`（既定、左から右）・`v`（上から下）、`m-tree` は `down`（既定）・`right`、`m-fishbone` は頭が右（既定）。`m-cycle` は 12 時の位置から時計回り。
- `m-timeline` の目盛りの置き方は `scale` 属性：`time`（既定、時間に比例）・`even`（等間隔。年の差が大きく偏るとき）。字は軸の上下に交互に置く。
- 箱と箱、箱と軸をつなぐ線は `--muted` の 3 px（`--line` は薄く、投影すると見えにくい。2026-10-23 の研修で確かめた）。`--line` は格子（と目盛りも字も持たない区切りの線）だけに使う。目盛りや字を持つ軸は情報なので `--muted`（年表の軸、その目盛りと目盛りの字。目盛りの字は図の字の大きさ）。`DECK.Plot` の軸（`m-curves`・`m-scatter`）は `--fg` のまま。矢じりは全パーツで同じ形。強調の線は `tone` の色。
- **字のコントラスト**：パーツの字はどれも、下にあるもの（地・箱の塗り）に対して 4.5:1 以上（既定・国語・ビジネスのテーマで。`tools/test-contrast.mjs` が測る）。情報を運ぶ字（箱の字・線の名前・値）は `--fg` か `tone` の色、`--muted` は補足だけ。`--muted` の補足を色の付いた地（`--emph-tint` など）に載せるときは、4.5:1 に届かなければ `--fg` にする。
- 図の「主な線」（特性要因図の背骨、年表の軸）は 1 本だけ 5 px まで太くしてよい。
- `m-flow` の線はもともと `--fg` で、`--muted` の線より濃いので変えない。線の名前と `muted` の箱の字は v1.2.0 で `--fg` にした（作者の承認。今ある資料の見た目が変わる。issue #1）。
- 縦書きはしない（国語のパーツだけ）。

### 2.4 ステップの順（既定）

AI への指示に入れる表（parts-map の 10 の「steps」の欄）に合わせる。

| パーツ | 既定のステップ | 変え方 |
|---|---|---|
| `m-timeline` | 1 つの出来事ずつ、時間の順。軸は最初の出来事と一緒に出る | `per-step`、箱の `step` |
| `m-cycle` | 1 つのステップずつ。最後から最初へ戻る矢印は最後のステップと一緒に出る | `per-step`、箱の `step` |
| `m-tree` | 上から 1 段ずつ（根、子の段、孫の段…） | `by="level"`（既定）・`by="node"`（1 つずつ） |
| `m-fishbone` | 原因が先、結果が後：大きな骨を 1 本ずつ（その原因と一緒に）、最後に頭（結果） | `order="causes-first"`（既定）・`order="effect-first"`（頭と背骨を先に） |
| `m-flow` | 今のまま（箱と線の `step`） | — |

どのパーツも、箱の `step` を書けばそれが勝つ。線のステップの既定は、両端の箱の遅いほう（`m-flow` と同じ）。

### 2.5 箱と線の図の見せ方

1 の決まりに従い、4 つで同じ名前を使う：

- `fade`（0）：箱がフェードして現れ、線はそのあとに引く（`m-flow` の今の見せ方と同じ）
- `draw`：先に線を引き、線の先に箱が現れる
- `grow`：箱が親（または前の箱）の位置から伸びて定位置に動く

`draw` と `grow` の動きは、全体で `fade` の長さと動く距離の中に収める（見せ方 0 より多く動かさない、1.2）。

## 3. グラフのパーツ

`m-scatter` `m-pie` `m-compare` `m-venn` は箱と線の図ではないが、属性の名前を今のパーツとそろえる。

- 軸のあるもの（`m-scatter`）は `m-curves` と同じ名前：`xr` `yr`（範囲）、`xt` `yt`（目盛り）、`xf` `yf`（目盛りの書式）、`xl` `yl`（軸の名前）。`m-sweep` も同じ名前だが、`xf` `yf` はない。
- 数を見せるものは `unit` `digits`（`m-bars`・`m-kpi` と同じ）。
- グラフのパーツは系列の語を 1 つにそろえる：`label`、`tone`、`step`、`at`（ステップの中の開始秒）、`anchor`（名前の向き：`right` `left` `above` `below`。`top` `bottom` も `above` `below` の別名として受け付ける）、`labelAt`（線の名前を置く x の値）。`m-curves` の古い `color`・`at`（名前の x）・`anchor` の `start` `middle` `end` は今も動くが、説明には書かない（`at` はほかのパーツと意味がぶつかるので、`m-curves` では開始秒としては使わない）。
- ステップの既定は 2.4 と同じく AI への指示の表から：散布図は点を出してから傾向の線、ベン図は集合を出してから重なり、比べる図は一方を出してからもう一方、それから違い。円グラフは一度に全部（1 切れずつ出すのは、台本が 1 切れずつ話すときだけ）。
- 積み上げ棒は `m-bars` の属性として足す（`stack`）。見せ方 0 の描画は変えない。

## 4. 伝えたいことの宣言

### 4.1 伝えたいことの一覧

パーツが答える「伝えたいこと」の一覧を、パーツライブラリに 1 つのファイルで持つ（`purposes.json`）。新規作成の札（タイル）もここから作る：`tile` は `"own"`（自分の札）・`{"into": id}`（その札に入る）・`"none"`（札を持たず、教科のパーツの組から入る）、`label` は札の短い名前、`icon` は絵の名前、`examples` は札の小さな字。予約の id は、パーツができるまで札を持たない（パーツと一緒に `tile` の案を出し、公開のときに規格化か、札が増えるなら作者が確かめる）。中身は parts-map の 8・10 の表の項目で、それぞれに `id`、日本語と英語の名前、既定のステップの言い方を書く。

| id | 伝えたいこと | 既定のステップ |
|---|---|---|
| `compare` | 量を比べる | 一方を出し、それから違い |
| `ranking` | 順位 | 並べ替えた棒を 1 本ずつ |
| `change` | 時間での変化 | 線を 1 本ずつ |
| `part-whole` | 全体と内訳 | 一度に全部 |
| `key-number` | 1 つの大事な数字 | 一度に全部 |
| `process` | 手順・工程 | 1 つの手順ずつ |
| `timeline` | 年表・予定 | 1 つの出来事ずつ |
| `cause-effect` | 原因と結果 | 原因、それから結果 |
| `cycle` | 循環 | 1 つのステップずつ |
| `hierarchy` | 階層・分類 | 上から |
| `position` | 位置づけ（2 軸） | 軸、それから項目 |
| `overlap` | 重なり | 集合、それから重なり |
| `correlation` | 2 つの量の関係 | 点、それから傾向 |

### 4.1.1 README で別のパーツに触れるとき

AI への指示には、その資料で使えるパーツの README だけが入る。Studio は、指示に入っていないパーツの名前を含む節を落とす。なので、別のパーツへの言及（「量を比べるなら `m-bars`」「名前と意味は `m-curves` と同じ」）は、**独立した 1 文か、文の最後の丸かっこ**にする。属性の説明の途中に混ぜない（落ちると属性の説明ごと消える）。パーツどうしのそろえの注（「m-tree と同じ」）は、作る人向けなので `<!-- llm: omit -->` に書くか、書かない。

## 6. 操作できるパーツ

学習者が押したり入力したりできるパーツを「操作できるパーツ」と呼ぶ（2026-10-25、規格化の確認と作者の決定）。今は `m-predict`（数を数える・予想を押す）、`m-kobun`（助動詞を押すと札）、`m-menu`（札がリンク）。

- **印は index.js に書く**：パーツのクラスに `static interactive = true;`。学習者の入力（仕様 §8.4「Viewer input」）を受け付けるパーツは、さらに `static viewerInput = true;`（`m-predict` だけ）。README の frontmatter には書かない（AI への指示に入るので）。経った時間そのものを見せるパーツ（`m-timer`）は `static clock = true;`：動きを減らす設定でも、実行系は実時間の t で描く（飾りの動きだけを止める。仕様 §9.1）。`tools/release.mjs` が manifest.json の `components.<名前>.interactive`・`.viewerInput`・`.clock`（true のときだけ）にする。
- **試験**：`tools/lint.mjs` が index.js を簡単に調べ、`input(…)` のメソッド、click・pointer・key・input・change などの受け取り、`a`・`button`・`input` の要素を作ること、子のリンクをデータにすること（`static shape = {links: true}`）のどれかがあって `static interactive = true` が無ければ誤りにする。`viewerInput` だけで `interactive` が無いのも誤り。
- **見せ方（色だけに頼らない）**：CATALOG.md ではパーツの名前の横に「操作できる」。gallery のパーツの説明の 1 枚では「操作できる / Interactive」の札と、説明の字を `--accent2` の破線の枠で囲む。各パーツの demo.html の 1 枚目の本文の最初に「操作できる」の札（27 px、破線の枠）。見出し（h2）には入れない（Studio がスライドの題と鍵に使うので）。

## 7. 道具（頼まれたときだけ使うパーツ）

新規作成では、標準パーツはいつも入り、教科のパーツの組と「道具」は使う人が選んだときだけ入る（作者、2026-10-25）。道具は、伝えたいことではなく、頼まれたときだけ使うパーツ（`m-timer` など）。

- **印は index.js に書く**：`static group = "tool";` と、新規作成の道具の札 `static tile = {"label": {"ja", "en"}, "examples": {"ja", "en"}, "icon"};`（1 行の JSON）。README には書かない。`tools/release.mjs` が manifest.json の `components.<名前>.group`・`.tile` にし、Studio は `group: "tool"` のパーツから「道具」の札の段を作る。
- **試験**：`tools/lint.mjs` は、`group` が `"tool"` 以外なら誤り、道具に札（`label`・`examples`・`icon`）が無ければ誤りにする。
- 道具の伝えたいこと（`m-timer` の `timebox`）は、伝えたいことの札を持たない（`tile: "none"`）。伝えたいことの札（使う人が外す）と、道具の札（使う人が選ぶ）を混ぜないため。
