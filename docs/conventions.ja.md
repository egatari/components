## 1. 見せ方の種類とシード値

### 1.1 何のためか

同じ部品がいつも同じ見せ方で出ると、資料がどれも同じに見えて飽きる（数字の札がいつも数え上げる）。そこで部品ごとに見せ方を何種類か持ち、資料に書いたシード値で選ぶ。**資料の中ではそろえ、資料ごとに変える**。

### 1.2 見せ方が変えてよいもの、変えてはいけないもの

見せ方が変えてよいのは、段階の中で**どう現れるか、どこに目を向けさせるか**だけ。

| 変えてよい | 変えてはいけない |
|---|---|
| 現れ方（フェード・下から・桁ごと・線を引く など） | 段階の数（`steps`） |
| 段階の中の動きの順（左から／大きい順 など） | 段階の長さ（`duration(k)`）と合図（`cues(k)`） |
| 注目の印（下線・枠）の有無 | 最後の状態（`t = Infinity`）が伝える中身：字・数・位置・色の意味 |
| | 使う色（テーマの変数だけ） |
| | 動きの量の上限（長さ・距離・回数を、見せ方 0 より大きくしない） |

段階の数と長さと合図を変えないので、口述原稿・動画の時間・字幕・授業の表示・印刷・読み上げは、見せ方によらず同じになる。

- **動きは注目を導くためだけに使う。** 跳ね続ける、回り続ける、揺れ続けるなどの飾りの動きは入れない。どの見せ方も、段階の中で動き終わって止まる。
- **動きを減らす設定（`prefers-reduced-motion`）は、どの見せ方でも守られる。** 実行系がこの設定のときは `t = Infinity` で描く（`kit/deck.js`）。なので、どの見せ方でも最後の状態だけで読めること。最後の状態に注目の印（下線など）が残る見せ方は、止まった絵でも意味が通る印に限る（「この数字が大事」を表す下線はよい。動いていないと分からない印はだめ）。
- **授業の表示**（`ctx.mode === "lecture"`）で先の段階を薄く見せる部品は、見せ方によらず同じ薄さ（0.45〜0.5、backlog #86）にする。
- **見せ方 0** は、今ある部品では今の見せ方そのもの。新しい部品では、いちばん控えめな見せ方（フェードして現れる）。

### 1.3 属性

| 置き場所 | 書き方 | 意味 |
|---|---|---|
| 資料 | `<html data-egatari-seed="N">` | 資料のシード値。N は 0 以上の整数（2³² 未満）。資料の元の根の要素に 10 進の整数で書く。新規作成のときに 1 回だけ書き、保存のたびに残す（変えない）。無いときは 0（仕様 [§8.4](https://github.com/egatari/egatari-spec/blob/main/egatari-1.0.md#84-component-contract-summary)） |
| 部品 | `seed="N"` | その部品だけシード値を上書きする |
| 部品 | `variant="名前"` | 見せ方を名前で直接選ぶ（人が「数え上げで」と言ったときなど）。シード値より強い |

選ぶ順：`variant` → 部品の `seed` → 資料の `data-egatari-seed` → 0。

- `variant` に知らない名前が書いてあれば、警告（`console.warn`）を出して見せ方 0 にする。
- `seed` と `variant` はどの部品にも共通の属性で、`static props` には書かない（今の部品の属性の名前とは重ならない。確かめ済み）。

### 1.4 選び方

部品は見せ方の名前の並びを宣言する。0 番目が見せ方 0。

```js
static variants = ["count", "rise", "flip", "underline"];
```

README の frontmatter にも同じ並びを書く（`variants: count, rise, flip, underline`。CATALOG.md に載る）。

シード値 s から見せ方を選ぶ：

1. s = 0 なら見せ方 0。
2. s ≠ 0 なら、見せ方の名前 v ごとに h(s, タグ名, v) を計算し、いちばん大きいものを選ぶ。h は `"<s>|<タグ名>|<v>"` の FNV-1a に、`kit/deck.js` の `rng` と同じかき混ぜをかけた 32 ビットの値。

この選び方から、次のことが言える。

- **資料の中では、同じ部品は同じ見せ方になる**（s とタグ名が同じなので）。資料のそろいが保たれる。1 つだけ違えたいときは、その部品に `seed` か `variant` を書く。
- **部品が違えば選ばれ方も違う**（タグ名が h に入るので）。`m-kpi` が数え上げの資料で `m-bars` も必ず同じ系統になる、ということはない。
- **後から見せ方を足しても、見た目が変わる資料は少ない。** 見せ方が n 種類から n+1 種類になると、変わるのは新しい見せ方が最大になった資料（およそ 1/(n+1)）だけ。余りで選ぶ方法（s mod n）だと、ほとんどの資料が変わる。
- 見せ方の名前は一度出したら変えない（名前が h に入るので）。やめるときは並びから外す（その見せ方だった資料だけが変わる）。

見せ方の中で揺らぎが要るとき（札の出る順を混ぜるなど）は、同じ h から作った決まった乱数を使う。`Math.random` は使わない（今までどおり）。

### 1.5 部品がシード値を読む方法

選び方の小さな関数を `tools/variant.js` に置き、`tools/expr.js` と同じ仕組みで使う部品に写す（`node tools/variant-sync.mjs`、印の付いた区画を上書きする。試験が写し忘れを見つける）。部品の中では次のように読む。

```js
// mount の中で 1 回
this.variant = variantOf(this);   // "count" | "rise" | …
```

`variantOf` は `variant` 属性 → `seed` 属性 → `document.documentElement` の `data-egatari-seed` → 0 の順に読み、1.4 のとおりに選ぶ。

Studio の部品の基底クラス（`DECK.MotionElement`）に同じものを持たせる案もある（`this.variant`）。そうなれば写した関数は要らなくなるが、Studio の変更なので dev と相談する（v0.4.8 の後）。それまでは部品庫の中だけで完結させる。

### 1.6 今ある部品に見せ方を足すとき

- **見せ方 0 の描画は 1 画素も変えない。** シード値の無い資料（今あるすべての資料）は、見た目が変わらない。試験では、各部品の demo のスクリーンショット（段階の途中と最後）を、見せ方を足す前の版のものと比べる。
- 資料は部品の版を固定している（仕様 [§6](https://github.com/egatari/egatari-spec/blob/main/egatari-1.0.md#6-components-and-profiles)）。なので、シード値のある資料の見た目が変わるのは、作者が部品の新しい版に移したときだけ（1.4 のとおり、およそ 1/(n+1)）。部品の版を上げるときは何が変わるかをもう見せているので、見せ方の変化もその 1 つとして見せる。見せ方を足すのは minor 版とし、CHANGELOG に書く。
- `static props` で今ある属性と見せ方が重なるときは、属性を優先する。例：`m-kpi` の `count="false"` は今までどおり「数えない」。数えることが前提の見せ方（`count`・`flip`）が選ばれていても、数えない見せ方（`rise`）にし、なぜ見せ方が変わったかを `console.info` で 1 回だけ知らせる。
- v1.2.0 で見せ方を足すのは `m-kpi` だけにし（飽きるという指摘のもとなので）、ほかの部品は次の版から足していく。

### 1.7 例：`m-kpi`

| 見せ方 | 段階の中の動き | 最後の状態 |
|---|---|---|
| `count`（0、今の見せ方） | 札が下から 14 px 上がりながら現れ、数字が `from` から最後の値まで数え上がる（初めに速く、終わりにゆっくり）。増減の行は数え終わる少し前に現れる | 数字・名前・増減・一言 |
| `rise` | 数字は初めから最後の値。札が下から上がりながら現れ、数字だけ少し小さい大きさ（0.85 倍）から元の大きさに戻る | 同じ |
| `flip` | 札が現れたあと、数字が右の桁から左の桁へ 1 桁ずつ、0 から最後の数字まで縦にめくれて止まる | 同じ |
| `underline` | 札が現れ、数字が初めから最後の値で出たあと、数字の下に `--term` の線を左から右へ引く | 同じ＋数字の下の線 |

どれも段階の長さは今と同じ（`at + dur`、増減があれば ＋0.4 秒）で、合図（`cues`）も同じ。動きを減らす設定のときは、どれも最後の状態がそのまま出る。

## 2. 箱と線の図（年表・循環・木・原因と結果）

### 2.1 方針：座標を書かせない

`m-flow` は箱の座標（px）を書く部品で、図の形を手で決めたいときにはよい。しかし AI が書くと、重なり・はみ出し・ずれが起きやすい。新しい 4 つ（`m-timeline` `m-cycle` `m-tree` `m-fishbone`）は、**中身とつながりだけを書き、並べ方は部品が決める**。

`m-flow` はそのまま残す（座標を書く図のため）。新しい 4 つは、箱と線の欄の名前を `m-flow` とそろえる。

### 2.2 データの形

子の JSON はどれも `{"nodes": [...], "edges": [...]}` の形。`edges` は省ける。

**箱（node）の共通の欄**（`m-flow` と同じ名前）：

| 欄 | 意味 |
|---|---|
| `id` | 文字か整数。つながりを書くときに使う |
| `label` | 箱の字（短く。`\n` で改行。`*斜体*` `_下付き` `^上付き` は `m-flow` と同じ）。または `tex`（KaTeX） |
| `note` | 箱の下の小さな字（`--muted`）。補足・年号の注など |
| `tone` | `term`（既定）・`emph`・`muted`・`accent2`・`series-1..4` |
| `step` | その箱が出る段階（書かなければ 2.4 の既定） |
| `at` | 段階の中の開始秒 |

**部品ごとの欄**：

| 部品 | 欄 | 意味 |
|---|---|---|
| `m-timeline` | `when`、`end` | 時点（数か `"1868"` `"2026-10"` `"2026-10-24"` の形の字）。`end` があれば期間（帯で描く） |
| `m-cycle` | （並びの順） | 並べた順に回る。最後から最初へ戻る矢印は自動で引く |
| `m-tree` | `parent` | 親の `id`。`parent` の無い箱が根（1 つだけ） |
| `m-fishbone` | `parent` | 親の `id`。`parent` の無い箱が大きな骨（分類：人・機械・方法・材料 など）、その子が原因、孫が細かい原因（3 段まで）。結果（頭）は `{"effect": {"label": …}}` で別に書く |

**線（edge）**：並び・親子から決まる線は自動で引くので書かない。`edges` に書くのは、それ以外のつながり（木の枝をまたぐ関係、原因どうしの関係など）だけで、欄は `m-flow` と同じ（`from` `to` `label` `tone` `dash` `step`）。既定は破線。

例（年表）：

```json
{"nodes": [
  {"id": "a", "label": "明治維新", "when": "1868"},
  {"id": "b", "label": "大日本帝国憲法", "when": "1889", "note": "発布"},
  {"id": "c", "label": "日清戦争", "when": "1894", "end": "1895", "tone": "emph"}
]}
```

### 2.3 並べ方の決まり

- **要素の箱の中に収める。** 字の大きさは要素の大きさから決め、収まらなければ小さくする。下限は 24 px（Studio の検査が図の中の字に求める大きさ。本文は 27 px）。下限より小さくはせず、下限でも収まらないときは `console.warn` で知らせる（試験もこれを見る）。わざと小さくする字（補足・目盛りの字）には `data-annot` を付ける（`m-kanbun` と同じ。検査の `smallSvgText` はこれを除く）。
- 箱の幅は字数から見積もる（`m-kpi` と同じ。字の読み込みを待たない）。箱どうし、字と線は 4 px より近づけない（`tools/test-components.mjs` が見る。`m-flow` と同じ）。
- 向きは `orient` 属性：`m-timeline` は `h`（既定、左から右）・`v`（上から下）、`m-tree` は `down`（既定）・`right`、`m-fishbone` は頭が右（既定）。`m-cycle` は 12 時の位置から時計回り。
- `m-timeline` の目盛りの置き方は `scale` 属性：`time`（既定、時間に比例）・`even`（等間隔。年の差が大きく偏るとき）。字は軸の上下に交互に置く。
- 線は `--line` の 3 px、矢じりは全部品で同じ形。強調の線は `tone` の色。
- 縦書きはしない（国語の部品だけ）。

### 2.4 段階の順（既定）

AI への指示に入れる表（parts-map の 10 の「steps」の欄）に合わせる。

| 部品 | 既定の段階 | 変え方 |
|---|---|---|
| `m-timeline` | 1 つの出来事ずつ、時間の順。軸は最初の出来事と一緒に出る | `per-step`、箱の `step` |
| `m-cycle` | 1 つの段階ずつ。最後から最初へ戻る矢印は最後の段階と一緒に出る | `per-step`、箱の `step` |
| `m-tree` | 上から 1 段ずつ（根、子の段、孫の段…） | `by="level"`（既定）・`by="node"`（1 つずつ） |
| `m-fishbone` | 原因が先、結果が後：大きな骨を 1 本ずつ（その原因と一緒に）、最後に頭（結果） | `order="causes-first"`（既定）・`order="effect-first"`（頭と背骨を先に） |
| `m-flow` | 今のまま（箱と線の `step`） | — |

どの部品も、箱の `step` を書けばそれが勝つ。線の段階の既定は、両端の箱の遅いほう（`m-flow` と同じ）。

### 2.5 箱と線の図の見せ方

1 の決まりに従い、4 つで同じ名前を使う：

- `fade`（0）：箱がフェードして現れ、線はそのあとに引く（`m-flow` の今の見せ方と同じ）
- `draw`：先に線を引き、線の先に箱が現れる
- `grow`：箱が親（または前の箱）の位置から伸びて定位置に動く

`draw` と `grow` の動きは、全体で `fade` の長さと動く距離の中に収める（見せ方 0 より多く動かさない、1.2）。

## 3. グラフの部品

`m-scatter` `m-pie` `m-compare` `m-venn` は箱と線の図ではないが、属性の名前を今の部品とそろえる。

- 軸のあるもの（`m-scatter`）は `m-curves`・`m-sweep` と同じ名前：`xr` `yr`（範囲）、`xt` `yt`（目盛り）、`xf` `yf`（目盛りの書式）、`xl` `yl`（軸の名前）。
- 数を見せるものは `unit` `digits`（`m-bars`・`m-kpi` と同じ）。
- 段階の既定は 2.4 と同じく AI への指示の表から：散布図は点を出してから傾向の線、ベン図は集合を出してから重なり、比べる図は一方を出してからもう一方、それから違い。円グラフは一度に全部（1 切れずつ出すのは、口述原稿が 1 切れずつ話すときだけ）。
- 積み上げ棒は `m-bars` の属性として足す（`stack`）。見せ方 0 の描画は変えない。

## 5. 決まったことと、後に回したこと

規格化の確認（2026-10-24）で次のように決まった。

1. 資料のシード値は `data-egatari-seed`（仕様 §8.4、egatari-spec 270767a）。
