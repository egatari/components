# 地図部品のデータ源の比較と設計案（Egatari components）

作成日：2026-10-24　対象：部品庫 `egatari/components` に提案する地図の部品（仮称 `m-map-world` / `m-map-japan`）

> 設計の下書き。部品はまだ作っていない。規格化の確認（2026-10-24）で決まったことは §5.4・§5.5・§6 に書いた。領土の描き方と国・地域の名前は作者が決めるまで保留で、コードに既定を入れない。

## 0. 結論（先に）

| 地図 | データ源 | 形式 | 置き場所 | 帰属表示 |
|---|---|---|---|---|
| 世界の国・地域 | Natural Earth 1:10m の **日本の見解版**（`ne_10m_admin_0_countries_jpn`、v5.1.1、パブリックドメイン）を、日本とその周辺だけ細かく、ほかは粗く簡略化 | 量子化した TopoJSON（作るときに投影を済ませておく） | 部品のコード（`index.js`）に埋め込む。世界と日本は**別の部品**に分ける | 法的には不要。README と授業の情報欄に「Natural Earth（パブリックドメイン）を加工」と書く |
| 日本の 47 都道府県 | Natural Earth 1:10m admin-1 の日本 ＋ 上の日本の見解版から北方四島と竹島を補う（どちらもパブリックドメイン） | 同上 | 同上 | 同上 |
| （市区町村、年代ごとの行政区域が要るとき） | 国土数値情報 行政区域 N03（CC BY 4.0） | 同上 | 別の部品か、版を分ける | CC BY 4.0 の出典表示と加工の表示が必須（§2.2） |

要点：

- 授業 1 つにかかる大きさ（実測）は、世界の地図で約 107 KB（gzip で約 31 KB）、47 都道府県で約 35〜46 KB（gzip で 11〜14 KB）。部品を分ければ、地図を使わない授業には 1 バイトも加わらない。
- **既定の Natural Earth（1:110m・1:50m）と world-atlas は北方四島をロシアとして描く**。日本の学校の教材には使えない。日本の見解版は 1:10m しか配布されていないので、自分で簡略化する。
- 国土数値情報 N03 は内容としては一番よい（2026-01-01 時点、北方四島・竹島・尖閣諸島を正しい県に含む）が、CC BY 4.0 なので帰属の表示が必須になる。さらに、ページに「測量法に基づく国土地理院長承認（複製）」とあり、簡略化したデータを MIT の配布物に入れて再配布してよいかは確かめきれなかった。都道府県の粒度ならパブリックドメインで足りるので、最初の版では N03 を使わない。
- 世界の地図を日本中心（中央経線 150°E）にすると、継ぎ目が 30°W に移ってグリーンランドを切る。また、大西洋を横切る矢印（三角貿易など）は描けなくなる。このため「太平洋中心」と「大西洋中心」の 2 つの見え方を用意する案を示す（§5.3）。

## 1. 前提（部品庫と仕様から来る制約）

調べた資料：`components/CONTRIBUTING.md`、`components/README.md`、`spec/egatari-1.0.md`（§2, §6, §8.4, §11）。

1. **授業には、使った部品のコードだけが入る**。index には `components used`（spec §3.1, §6）が記録され、実行の層には再生に要る部品のコードが入る。したがって、地図のデータを部品の中に入れても、その部品を使う授業だけが重くなる。
2. **Core の形の授業には、部品庫の部品以外の実行コードを入れられない**（spec §6）。地図ごとに JS のデータ用モジュールを授業に同梱すると「実行できるスクリプト」とみなされ、授業は Extended になる（編集のときに砂場で動かす、利用者への告知が要る、など）。JSON のデータ塊（`<script type="application/json">`）なら実行コードではないが、§4 の実行時の JSON ブロックに新しい種類を足すには仕様の改定が要る。
3. **部品のコードに `import` を書けない**（`tools/scan-code.mjs` が禁止）。d3-geo を import できない。中に貼り込むこともできるが、走査に引っかかる語（`Function`、`constructor` など）が混じるおそれがある。投影と経線での切断は、部品を作る段階（ビルド）で済ませておくのが安全。
4. **部品の同一性のハッシュは `index.js` だけを覆う**（spec §6）。地図のデータを index.js に入れれば、国境線もハッシュで固定される。線を直したら新しい版になる（README の「見た目が変わる変更は minor 以上」の決まりに合う）。
5. **文字は 24 px 以上**（部品庫のテスト）。1280×720 の舞台で 47 都道府県すべてに名前を付けることはできない。名前は強調した地域だけに付ける。出典の一行を 24 px で地図の上に書くのも大きすぎるので、帰属表示が必須になるデータは避けたい（§2.2）。
6. **自己完結**（spec 冒頭、§11）。表示のときに外へ取りに行くことはできない。外部のタイル（地理院タイル、OSM タイルなど）は使えない。

### 2.1 Natural Earth（パブリックドメイン）

- 利用条件（確認済み）：<https://www.naturalearthdata.com/about/terms-of-use/>
  「All versions of Natural Earth raster + vector map data found on this website are in the public domain.」「No permission is needed to use Natural Earth. Crediting the authors is unnecessary.」
  推奨の表示：「Made with Natural Earth.」または「Made with Natural Earth. Free vector and raster map data @ naturalearthdata.com.」
- 版：5.1.1（ダウンロードした zip 内の `VERSION.txt` で確認）。
- **国境の描き方**：既定では実効支配の線（de facto）。ダウンロードした 1:10m の README に「Natural Earth shows de facto boundaries by default ... Optional point-of-view (POV) variants are available」とある。
  - **日本の見解版** `ne_10m_admin_0_countries_jpn.zip` は 1:10m だけ存在する（50m・110m の同名 URL は HTTP 403 で、存在しないと判断）。<https://naciscdn.org/naturalearth/10m/cultural/ne_10m_admin_0_countries_jpn.zip>
- ダウンロードしたデータで点検した結果（点が多角形の中に入るかで判定）：

| 地域 | 既定 1:110m | 既定 1:50m | 日本の見解版 1:10m |
|---|---|---|---|
| 日本の多角形の数 | 3（四国・北海道・本州と九州。沖縄なし） | 34（沖縄・先島・奄美・父島・八丈島あり） | 114（南鳥島・尖閣・竹島まで） |
| 北方四島 | 描かれない | **ロシア** | **日本** |
| 竹島 | なし | なし | 日本（ごく小さい） |
| クリミア | ― | ロシア | ウクライナ |
| 西サハラ | ― | モロッコ | 西サハラ（別の地域） |
| 南樺太・千島（得撫以北） | ロシア | ロシア | ロシア（§4 参照） |
| 台湾 | TWN | TWN | TWN（`NAME_JA` は「中華民国」） |

- admin-1（都道府県）：1:10m に日本の 47 都道府県がある（`iso_3166_2` は JP-01〜JP-47、`name_ja` 付き）。これは既定の見解の版で、**北方四島と竹島を含まない**。尖閣諸島・南鳥島は含む。沖ノ鳥島は含まない。日本の見解版の国の多角形から admin-1 を差し引くと、残るのは北方四島（4 片）と竹島だけだった。これを北海道（JP-01）と島根県（JP-32）に足せば、パブリックドメインだけで 47 都道府県がそろう（実際に作って確かめた。§3）。
- 1:50m の admin-1 は日本を県単位で持っていない、という記憶があるが、今回は確かめていない（未確認）。

### 2.2 国土数値情報 行政区域（N03）

- データのページ（確認済み）：<https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html>
  - 利用条件は「オープンデータ（CC_BY_4.0）」。
  - 2026 年（令和 8 年）版、基準日は 2026 年 1 月 1 日、2026 年 4 月に更新。測地系は JGD2011。
  - ページに「測量法に基づく国土地理院長承認（複製）R 7JHf 351」とある（2025 年版は R 6JHf 503）。
  - 境界未定地には暫定の境界線を引いた、との注意がある（一覧：<https://nlftp.mlit.go.jp/ksj/gml/datalist/N03_Boundary_undetermined.pdf>）。
- サイト全体の利用規約（確認済み）：<https://nlftp.mlit.go.jp/ksj/other/agreement.html>（2026 年 3 月 23 日施行）
  - 権利の表示がないものには「公共データ利用規約（第1.0版）」（PDL1.0）を適用する、とある。
  - 出典の記載例：「出典：国土交通省国土数値情報ダウンロードサイト（当該ページのURL）」
  - 加工したときの例：「「国土数値情報（○○データ）」（国土交通省）（当該ページのURL）をもとに○○株式会社作成」。また「編集・加工した情報を、あたかも国が作成したかのような態様で公表・利用してはいけません」。
  - CC BY 4.0（一部制限）のデータは、個別のページに書かれた条件が優先する。
- 個別のデータに使う規約（確認済み）：<https://nlftp.mlit.go.jp/ksj/other/agreement_01.html>（制定は令和 2 年 4 月 1 日。政府標準利用規約に準拠し、CC BY 4.0 と互換）
  - 「商用利用も可能です。」
  - 「複製、公衆送信、翻訳・変形等の翻案等、自由に利用できます。」
  - 加工したときの例：「「国土数値情報（○○データ）」（国土交通省）（当該ページのURL）を加工して作成」
  - 加工したデータの再配布を個別に定めた条文はない。CC BY 4.0 の下では、表示を守れば翻案物の再配布は認められる。
- PDL1.0（確認済み）：<https://www.digital.go.jp/resources/open_data/public_data_license_v1.0>。1.7.3 で CC BY と互換とされている（令和 6 年 7 月 5 日制定）。出典の例：「出典：D庁ウェブサイト（当該ページのURL）、PDL1.0（規約原文ページのURL）」。
- **MIT または CC BY のリポジトリに入れられるか**：CC BY 4.0 なので入れることはできる。ただしリポジトリは「コードは MIT、データは CC BY 4.0」の混在になる。その場合、データのファイルごとに出典・加工の表示・CC BY 4.0 への参照を付け、配布物（tarball）にも NOTICE を入れる必要がある。さらに、CC BY の表示は「媒体に照らして合理的な方法で」行う義務があるので、**授業ごとに**出典を見える形で示す必要がある（情報欄で足りるかは要判断）。
- **測量法（未確認・要問い合わせ）**：N03 の境界は国土地理院の基本測量成果（数値地図（国土基本情報））をもとにしており、国交省が複製の承認を得ている。地理院の Q&A（<https://www.gsi.go.jp/LAW/2930-qa.html>）では、Web サイトや書籍に地図を図として挿入する場合は「原則として申請不要」で、出典を明示すればよい。ただし「ウェブサイトのメインコンテンツが地図である場合を除きます」とある。強く簡略化した境界線を**データとして**部品庫で再配布する場合に承認が要るかどうかは、どの資料にも書かれていなかった。国交省の国土数値情報の窓口か、国土地理院に問い合わせるのが確実。
- 北方四島・竹島・尖閣：2026 年版を都道府県ごとにまとめて確かめた。竹島（島根県）、国後・択捉・色丹・歯舞（北海道）、尖閣諸島（沖縄県）、沖ノ鳥島・南鳥島（東京都）がすべて入っている。
- 大きさ：全国版の zip は 803 MB。都道府県のシェープファイルは 183 MB で、多角形は 123,025 個。

### 2.3 地球地図日本（国土地理院）と dataofjapan/land

- 地球地図日本（確認済み）：<https://www.gsi.go.jp/kankyochiri/gm_jpn.html>
  - 「本データには、「国土地理院コンテンツ利用規約」が適用されます。」
  - 境界（行政界）は第 2.1 版で、2015 年 1 月 1 日時点。主に 1/100 万の国際図をもとにしている。
- 国土地理院コンテンツ利用規約（確認済み）：<https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html>（令和 7 年 11 月 20 日改正）
  - 特段の記載がなければ PDL1.0 を適用する。
  - 出典の例：「出典：国土地理院ウェブサイト（当該ページのURL）」。加工したときは、加工したことと、それを行った主体を別に書く。
- dataofjapan/land（<https://github.com/dataofjapan/land>）：README には「使用ライセンスは配布元に準じ、非営利目的の場合は「出典元(地球地図日本)の明記」を、営利目的の場合は（中略）「著作権者(地球地図日本)への利用報告」をお願いいたします」とある。リポジトリそのものにはライセンスの表示がない（GitHub API の `license` は null）。利用報告の要求は、現在の地理院の規約（PDL1.0）より古い条件と思われる。使うなら、配布元から直接取るほうがよい。データの中身は 2014 年頃の地方公共団体コードで、北方四島を含む。
- 地理院地図 Vector：地理院の「測量法に基づく承認」ページ（<https://www.gsi.go.jp/LAW/2930-index.html>）は、これを測量成果ではないものとして挙げ、「国土地理院コンテンツ利用規約に従ってご利用ください」としている。ただしタイルで配るので、47 都道府県の多角形を作るには手間がかかる。今回の目的には向かない。

### 2.4 e-Stat 境界データ

- e-Stat の利用規約（確認済み）：<https://www.e-stat.go.jp/terms-of-use>。政府標準利用規約（第 2.0 版）に準拠し、CC BY と互換。出典の例は「出典：政府統計の総合窓口(e-Stat)（https://www.e-stat.go.jp/）」。ただし**境界データは別紙で別の決まりがある**としており、その本文は確かめられなかった（`/gis-terms` は機能の規約だけを載せていた。**未確認**）。
- 中身は国勢調査の小地域（町丁・字）の境界で、都道府県の地図には細かすぎる。

### 2.5 world-atlas / us-atlas（npm）

- world-atlas 2.0.2：`package.json` によると ISC ライセンス。README には「a convenient redistribution of Natural Earth's vector data, version 4.1.0」とある（確認済み）。
- 中身は **Natural Earth 4.1.0 の既定の見解**。北方四島はロシア側になる。`countries-110m.json` は 108 KB（gzip で 38 KB、陸の object も含む）。自分で 5.1.1 から作れば同じ程度の大きさになるので、使う利点がない。
- us-atlas はアメリカ合衆国の州と郡で、今回の用途の外。

### 2.6 geoBoundaries / OpenStreetMap 由来のデータ

- geoBoundaries の API（確認済み）：<https://www.geoboundaries.org/api/current/gbOpen/JPN/ADM1/>
  - JPN ADM1 は `boundarySource: OpenStreetMap, Wambacher`、`boundaryLicense: Open Data Commons Open Database License 1.0`、表している年は 2017。
  - JPN ADM0 の出典は国土数値情報で、CC BY 4.0。
- OSM の著作権のページ（確認済み）：<https://www.openstreetmap.org/copyright>。データを改変したり、それをもとに作ったりして配布するなら「you may distribute the result only under the same license」（ODbL）。表示は「© OpenStreetMap contributors」に、ODbL であることを添える。
- 部品のコードに埋め込んだ境界は「派生データベース」にあたる。その部分を ODbL で提供する義務が生じ、MIT の部品庫と合わない。**採らない**。
- しかも、簡略化した JPN ADM1 には北方四島が入っていなかった（実測）。

### 2.7 時代ごとの境界（歴史）

- 上のデータ源のどれにも、世界の過去の国境は入っていない。
- 国土数値情報 N03 には 1920 年（大正 9 年）からの年版があり、日本の市町村の変化なら扱える（CC BY 4.0）。
- 世界の過去の国境：aourednik/historical-basemaps は GPL-3.0（GitHub API で確認）。コピーレフトなので埋め込みには向かない。CShapes 2.0 の条件は**未確認**（CC BY-NC-SA だったという記憶があるが、確かめていない）。
- 現実的な対応：最初の版では扱わない。授業の作り手が子の JSON に経度・緯度の簡単な多角形（戦線、勢力の範囲、律令国のおおよその形など）を書き、それを重ねて描ける口を用意しておく（§5.4）。

## 3. 大きさの実測

道具：mapshaper 0.6.102、d3-geo 3.1.1、d3-geo-projection 4.0.0。ダウンロードしたものの中のコードは動かしていない。属性は ID と日本語名だけを残した。TopoJSON の量子化は 1e4。SVG の経路は座標を小数 1 桁（0.1 px）に丸めた `d` 属性の合計で、`<svg>` の枠や属性名は数えていない。gzip は -9。

単純化は Visvalingam 法を使った。mapshaper の `interval=` は「線分の長さ」ではなく「消してよい三角形の面積の目安」として働く。このため、細長い島（沖縄本島など）は値を大きくすると消える。

読み取れること：

- **TopoJSON は SVG の経路より 3〜4 割小さい**（gzip しても 2 割ほど小さい）。境界を 1 本だけ持つので、塗り分けたときに隣どうしの境界線を 1 回だけ描ける。継ぎ目（南極の 180° など）に線を引かずに済む。
- 竹島・沖ノ鳥島・南鳥島・尖閣は、スライドの解像度ではどのデータ源でも面として残らない。**「必ず描く島」の点の一覧**（経度・緯度・名前・都道府県）を別に持ち、点で描く。大きさは 1 KB 未満。
- 授業の HTML は、手元で開くときには圧縮されない。地図 1 枚で 35〜110 KB 増える。音声入りの授業は数 MB あるので、大きな負担ではない。
- 実行時に要るコード（TopoJSON の解読、経路の文字列への変換、点の投影）は 2〜3 KB と見積もった（**見積もりで、実測ではない**）。

## 4. 政治的に注意の要る点（日本の学校の教材として）

- 高等学校学習指導要領（平成 30 年告示）の「内容の取扱い」（確認済み、内閣官房のまとめ <https://www.cas.go.jp/jp/ryodo/torikumi/mext_02.html>）：
  - 地理総合：「竹島や北方領土が我が国の固有の領土であることなど，我が国の領域をめぐる問題も取り上げるようにすること。その際，尖閣諸島については我が国の固有の領土であり，領土問題は存在しないことも扱うこと。」
  - 歴史総合と日本史探究：「北方領土に触れるとともに，竹島，尖閣諸島の編入についても触れること。」
  - 教員が作る授業は検定の対象外だが、学校で使う以上、この見解に沿う地図にしておくのが無難。
- **北方四島**：既定の Natural Earth、world-atlas、geoBoundaries（OSM）では日本の領土として描かれない。日本の見解版と N03 では北海道に入る。
- **竹島**：日本の見解版と N03 には入っている。面としては消えるので、点で描く。
- **尖閣諸島**：NE admin-1（沖縄県）、日本の見解版、N03 のどれにも入っている。単純化すると消えるので、点で描く。
- **南樺太と千島列島（得撫島以北）**：日本の見解版ではロシアになっている。日本政府は、サンフランシスコ平和条約で権利を放棄し、帰属について見解を述べる立場にない、としているとされる。また、地図帳ではここを「帰属未定」として白く塗ることが多いとされる。**どちらも今回は一次資料で確かめられていない（未確認）**。対応するなら、作る段階でロシアの多角形からこの部分を切り出し、「帰属未定」の地域として別の塗り方をする。
- **台湾**：日本の見解版では TWN として独立した多角形になっているが、`NAME_JA` が「中華民国」になっている。**日本語の名前は自前の表で上書きする**（外務省の「国・地域」の表記にそろえるなど）。部品の名前や README でも「国」ではなく「国・地域」と書く。
- **ほかの係争地**：日本の見解版では、クリミアはウクライナ、西サハラは独立した地域、コソボは独立した地域、パレスチナは PSX になっている。カシミールの線も日本の見解に従う、と NE は説明している。
- **都道府県の境界未定地**（富士山頂など）は、スライドの縮尺では見えない。
- 報道によると、Equal Earth の世界地図が北方四島をロシアと同じ色で塗っていたため、政府が訂正を求めたという（記事は開けず、**未確認**）。これは図法の問題ではなく色の問題。Equal Earth の図法を使うこと自体は差し支えない。

## 5. 推奨する設計

### 5.1 データの置き場所（3 案の比較）

| 案 | 長所 | 短所 |
|---|---|---|
| (1) 部品のコードに埋め込む | Core のまま。ハッシュで国境線も固定される。授業の作り手は ID を書くだけ | 部品が大きくなる（下の表）。データを直すと部品の版が上がる |
| (2) 授業の子の JSON で渡す | 部品は小さい。どんな地図でも描ける | 作り手（または AI）が 50〜100 KB の座標を書くことになり、元の原稿が膨らむ。同じ地図を何枚ものスライドで使うと、そのたびに複製される。国境の見解が授業ごとにばらつく |
| (3) 地図ごとのデータ用モジュールを授業に同梱 | 部品は小さい。地図を差し替えやすい | JS にすると実行コードになり、授業は Extended になる（spec §6）。JSON の塊にするなら、仕様に新しいブロックの種類を足す必要がある。ハッシュで固定されない |

**推奨：(1) とし、地図ごとに部品を分ける**。描画のコードは `tools/expr.js` と同じやり方で共有する（`tools/geo-sync.mjs` で各部品にコピーし、`USERS` に登録する）。(2) は、経度・緯度で書く小さな重ね描き（§5.4）にだけ使う。

| 部品（仮称） | index.js の見込み | 中身 |
|---|---|---|
| `m-map-japan` | 約 50〜60 KB | 47 都道府県（単純化 1000〜1500）、必ず描く島の点、県庁所在地 47 か所、描画のコード |
| `m-map-world` | 約 115〜230 KB | 太平洋中心の見え方 1 つで約 115 KB。大西洋中心も持つと約 230 KB（§5.3） |

既存の部品の index.js は 6〜43 KB（14 個で計 224 KB）なので、地図は大きいほうになる。それでも tarball は gzip で 50〜90 KB 増えるだけで済む。

### 5.2 形式とデータを作る手順

- 形式：**作る段階で投影を済ませた、量子化 TopoJSON**。座標は 1000 幅の基準の箱の上の整数を差分で持ち、SVG の viewBox で拡大・縮小する。各地物には ID と日本語名を持たせる。
  - 世界：`ADM0_A3`。NE には ISO と違う符号がある（KOS、SAH、SDS など）ので、ISO 3166-1 の alpha-3 との対応表を添え、作り手はどちらでも書けるようにする。
  - 日本：JIS の都道府県コード `01`〜`47`。`JP-13` や「東京都」とも書けるようにする。
- 境界線は `mesh(a !== b)` で 1 回だけ描き、海岸線とは分ける。塗りの多角形には線を付けない。こうすると継ぎ目に線が出ない。
- 作る手順は部品庫の `tools/maps/` に置き、誰がやっても同じ結果になるようにする：
  1. 出典の URL と、ダウンロードしたファイルの SHA-256 を記録する。
  2. mapshaper（版を固定）で切り出し、属性を整理し、単純化する。
  3. d3-geo（版を固定）で投影し、経線で切る。
  4. TopoJSON を index.js の印で挟んだ範囲に書き込む。

  完成したデータの SHA-256 は README に書く。
- 点（都市・島）と矢印の端点は経度・緯度で受け取り、部品の中にある小さな順投影の関数で座標に直す。Equal Earth・LCC・正距方位はどれも 10 行程度で書ける。

### 5.3 図法

- 世界は 2 つの見え方を用意する。
  - **`view="pacific"`（既定）**：Equal Earth 図法、中央経線 150°E。面積が正しいので、塗り分けた地図の印象をゆがめない。日本の地図帳と同じく、日本が中央に来る。
  - **`view="atlantic"`**：中央経線 10°E。大西洋をまたぐ矢印（三角貿易、大航海時代、移民の流れ）を描くのに必要。
  - 見え方ごとに約 107 KB かかる。2 つとも 1 つの部品に入れるか、`view` ごとに部品を分けるかは作者が決める（未決の 2）。
  - 日本の地図帳に近いのはミラー図法。こちらを選んでも大きさはほぼ同じ（113 KB）。
- 東アジアの地域図（正距方位図法、中心 135°E・35°N）は約 48 KB。必要なら 3 つ目の見え方にする。
- 日本は**正角円錐図法（標準緯線 30°・42°、中央経線 136°E）**とし、配置を 2 つ用意する。
  - `layout="inset"`（既定）：南西諸島と小笠原を枠の中に入れて描く。学校の地図でよく見る形。
  - `layout="true"`：実際の位置で描く。南鳥島・沖ノ鳥島まで含めると経度で約 31° の幅になり、本州から九州までは画面の半分ほどの大きさになる。
  - 北方四島、竹島、尖閣、沖ノ鳥島、南鳥島は、どちらの配置でも必ず点か面で描く。

### 5.4 部品の属性（おおまかに）

```html
<m-map-japan layout="inset" labels="focus" style="height:600px">
<script type="application/json">
{
  "regions": [
    {"id": "13", "tone": "emph", "step": 1},
    {"group": "kinki", "tone": "series-2", "step": 2}
  ],
  "values": {"01": 5.1, "13": 14.1},
  "classes": [0, 2, 5, 10],
  "points": [{"lon": 139.69, "lat": 35.69, "label": "東京", "step": 3}],
  "flows":  [{"from": "13", "to": "27", "value": 3, "step": 4}],
  "shapes": [{"label": "例：古代の国の範囲", "polygon": [[135.1,34.2],[136.0,34.2],[136.0,35.0]], "step": 5}]
}
</script>
</m-map-japan>
```

- `m-map-world` も同じ形にし、`view="pacific|atlantic"` を加える。`id` には ISO alpha-3 か NE の符号を書く。
- 段階：`step` ごとに、地域の強調、点、矢印（伸びていく線）、重ね描きを出す。地域の塗り分けは段階に応じて薄い色から濃くしていく。
- カメラ：地域の `path` に `data-mark="JP-13"` のような印を付ける。Studio の `{zoom:JP-13}` で、その地域へ寄れる。
- 色：テーマの変数だけを使う。段階のある塗り分けは、入力がすべてテーマの変数なら `color-mix()` で作ってよい（例：`color-mix(in oklab, var(--term) 40%, var(--bg))`。規格化、2026-10-24）。そのうえで：
  - 段階は色だけで分けない。凡例に値を書くほか、入る所には地域の上に値か段階の番号を書く（マウスを乗せたときだけ出る印や模様では足りない）。
  - 隣り合う段階の色のコントラストを、既定のテーマと国語のテーマの両方で 3:1 以上にする。測り方はテーマの指標（theme metrics）と同じにする。
- 地方区分の組（八地方区分など）は部品の中に持つ。
- 文字の扱い（静止画のとき）：最終の状態の文字の等価物として、強調した地域の名前と値を表にし、読める層に出す。

### 5.5 帰属表示の扱い

- 決まったこと（規格化、2026-10-24）：帰属は部品の README と、授業の添付・出典の欄に書く。Natural Earth は表示の義務はないが、それでも書く。N03 は後の版に回す。
- 推奨の構成（NE だけ）なら、法的な表示義務はない。それでも出所は README と NOTICE に書く。授業の情報欄にも、Studio が自動で「地図データ：Natural Earth（パブリックドメイン）を加工」と添えるのがよい。添え方は、授業の `attribution`（作り手の表示）とは混ぜないこと。部品の README の frontmatter に `data-credit` のような欄を足し、情報欄はそれを読む形が考えられる（未決の 4）。
- N03 を使う版を作る場合は、次の表示が必須になる（データのページと agreement_01 の例に従った案）：
  > 「国土数値情報（行政区域データ）」（国土交通省）（https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html）を加工して作成（加工：Egatari components の作成者。都道府県単位への統合・簡略化）。CC BY 4.0（https://creativecommons.org/licenses/by/4.0/deed.ja）
- 地球地図日本を使う場合：「出典：地球地図日本（国土地理院）（https://www.gsi.go.jp/kankyochiri/gm_jpn.html）を加工して作成」。PDL1.0 の例に合わせて、規約の URL も添える。
