# 入力を受け付ける部品の共通の決まり（下書き）

> 下書き（2026-10-25）。規格化と作者の確認の前。まだ部品は作らない。[共通の決まり](conventions.ja.md)（見せ方とシード値、箱と線、字のコントラスト）にはこの部品も従う。この文書はその上に足す決まり。仕様（§8.4、live 拡張）に書き足しが要りそうな所は「仕様へ」と印を付けた。

この部品の仲間（入力を受け付ける部品）は、見る人の手で値が変わる図である。表現の目録（`docs/expression-catalogue.md`）の不足 2「予想してから答えを開く」と不足 4「数値が反応する文章・記入表」が最初の 2 つ。

## 1. 入力はどこから来るか

同じ部品が、次の 3 つのどこから入力を受けても動く。部品は入力の出どころを知らなくてよい（同じ形の値を受け取る）。**主な使い方は A（発表者が入れる）**。学校では、生徒のスマートフォンで投票させるのは現実的でなく、iPad を配って準備するより手を挙げてもらう方が速い（作者、2026-10-25）。B（live）はあれば使える、付け足しの道。

| 出どころ | 場面 | 例 | 通信 |
|---|---|---|---|
| **A. 発表者（主）** | 授業で先生が入れる。黒板の代わり | 「A だと思う人〜」と手を挙げてもらい、数えて ＋1 を押す。算数で数をその場で変えて、答えが変わるのを見せる | 要らない |
| C. 一人で学ぶ人 | 自習 | 自分の予想を押してから答えを開く。数を変えて確かめる | 要らない |
| B. クラス（live、付け足し） | 生徒が自分の端末で答える | live の投票（`poll`）の集計を「クラスの予想」として出す | live 拡張だけ |

- **live が無くても、教材は A と C で全部使える**（B が無いときは、B の欄が出ないだけ）。
- A と C は同じ操作（部品の中の入力）で、違いは誰が操作するかだけ。

### 1.1 発表者が入れる（A）

- **映している画面の上で直接**：先生が投影の前でマウスか指で押す。
- **発表者の画面（`p`）から**：手元で押すと、映している画面が変わる。今ある `deck-cmd` の通り道で `{type: "input", key, id, value}` を送る（`key` は部品、`id` は入力の欄。形は dev と確かめる）。動画（`?mode=video`）では、画面は入力の指示を受け付けない。
- **予想・投票の部品の数え方**：選択肢ごとに数の欄と、大きな **＋1・−1 のボタン**（押せる大きさ 44 × 44 px 以上）を置く。手を数えながら押せる。数を直接打ち込むこともできる。数は 0 より小さくならない。
- **入れた数はすぐ出す**。「見せると決めた後だけ」の決まりは live の集計（B）にだけかかる。発表者が入れた数は発表者自身の入力なので、隠さない。
- **クラスの結果は、選択肢ごとの棒**で出す。見た目は `m-bars` とそろえる（棒の色・字・目盛りの付け方）。答えはこれまでどおり段階で開く。
- 数は、ほかの入力と同じく**段階に入ると戻る**。「クラスの数を残す」は、先生方から求められたら後で考える。

## 2. 状態と (i, k, t)

- 入力された値は**見る人の状態**で、(i, k, t) の外にある（Studio の約束事 §3、仕様 §8.4 の「見る人が手で変える部品」）。
- **段階に入ると（同じ段階に入り直しても）、作者の書いた初めの値に戻る**（`ctx.reset`）。授業で前の段階に戻ってまた進むと、入れ直しになる。授業の途中で値を残したいとき（数えた人数を後のスライドでも使う）は、v1 では扱わない（後で検討。「仕様へ」）。
- `render(k, t)` が描くのは、**作者の書いた初めの値と、作者の書いた答え**。入力はその上に重ねる。

## 3. 動画・印刷・発表者の画面に出るもの

| 出力 | 出すもの |
|---|---|
| 動画（`?mode=video`） | 作者の初めの値と、答えを開く段階では作者の答え。入力の欄は出さない（押せない） |
| 印刷・PDF | 最後の状態：作者の初めの値と答え。入力の欄は値の字として出す（「予想：＿＿」でなく、作者の書いた例の値） |
| 発表者の画面 | 映している画面と同じ。入力は発表者の画面からもできる |
| 動きを減らす設定 | 最後の状態。入力はできる（動かないだけ） |
| 授業の表示（lecture） | ほかの部品と同じ。先の段階は薄く |

**答えは段階で開く。** 「答えを開く」は入力の操作ではなく、作者が書いた段階（`step`）で開く。これで動画・印刷・口述原稿の時間が入力によらず決まる。自習（C）で、答えを開く前に自分の予想を選ぶのは段階の中の操作。

## 4. 入力の操作と、キーボード

- 入力の欄は、ふつうの HTML の入力（`<input type="number">`・`<input type="range">`・選択肢のボタン）を部品の中に置く。字は 24 px 以上、押せる大きさは 44 × 44 px 以上。
- キーボードだけで使える：Tab で数の欄（または ＋1・−1）に入り、`+`・`-` か矢印で数を変える。**数字のキーは割り当てない**（数字＋Enter はページへ飛ぶ操作のため）。数を直接打ち込むのは、欄の中にいるときだけ。**入力の欄にいるあいだは、矢印・Space・PageDown を部品が受け取り、スライドは進まない**（Studio #69 で、実行系は入力の欄の中のキーを、shadow root の中も含めて無視する。部品を作るときに main で確かめ、部品の入力の欄で試験を足す）。Esc で欄を出ると、スライドの操作に戻る。
- 読み上げソフト：欄には名前（`aria-label`）を付け、値が変わって計算し直した結果は `aria-live` で知らせる。
- 入力で変わるのは**値と、それから計算される値だけ**。並べ方・段階の数・色の意味は変わらない。
- 入力の範囲（最小・最大・刻み）は作者が書く。範囲の外は受け付けない。字の式を入れさせない（式は作者が書き、`tools/expr.js` で計算する）。

## 5. 値の形（作者が書くもの）

どの部品も、入力できる値を同じ形で書く。

```json
{"inputs": [
  {"id": "a", "label": "A だと思う人", "value": 12, "min": 0, "max": 40, "step": 1, "unit": "人"},
  {"id": "b", "label": "B だと思う人", "value": 8, "min": 0, "max": 40, "step": 1, "unit": "人"}
]}
```

- `value` は作者の初めの値。動画・印刷・最初の表示はこれ。
- 計算される値は `expr`（`tools/expr.js` の式。入力の `id` を変数に使える）で書く。
- 予想の部品は `choices`（選択肢）と `answer`（正しい選択肢の番号、答えを開く段階 `answerStep`）を持つ。live の `poll` と同じ形（選択肢は 0 から数える）にして、live の集計をそのまま受け取れるようにする。

## 6. live の集計を受け取る（B）

- live 拡張のある再生で、その段階の `poll` と部品の選択肢が対応しているとき（部品に `poll="p1"` と書く）、部品は集計（選択肢ごとの数）を受け取り、「クラスの予想」として出す。受け取るのは数だけで、誰が何を選んだかは受け取らない。
- 集計を出すのは**先生が結果を見せると決めた後だけ**。部品は集計を `ctx.live`（live の無い再生では `null`）から読むだけで、書き換えない。受け取るのは選択肢ごとの数だけ。
- **答えた人が少ないとき（暫定で 3 人未満）は何も出さない**（少人数のクラスで、誰が何を選んだかが分からないように。数は仕様で決まる）。
- live 拡張の「画面に何も足さない」は「つながった部品が、見せると決めた後の集計を出すほかは、画面に何も足さない」に書き換わる（規格化が live.md に書く、2026-10-25）。
- 集計は見る人の状態と同じ扱い：(i, k, t) の外、動画・印刷には出さない。

## 7. 口述原稿での触れ方

- 原稿は**作者の初めの値**で書く（「A だと思う人が 12 人、B が 8 人なら…」）。動画と字幕はこの値と一致する。
- 授業で値を変える場面は、原稿に `{note:ここで手を挙げてもらう}` と書く。読み上げず、字幕にも出さず、発表者の画面にだけ出る（規格化が仕様 §8.2 に足す）。**丸かっこ（…）は使わない**（今は読み上げられる）。
- 入力によって変わる数を、原稿が読み上げることはない（読み上げは作者の値だけ）。

## 8. 言いたいことと名前

- 予想してから答えを開く部品：言いたいことの一覧に `predict`（予想してから確かめる）を足す。
- 数値が反応する部品：`explore`（数を変えて確かめる）を足す。`parameter`（パラメータを動かす。m-sweep）とは、作者の段階で動かすか、見る人が動かすかで分ける。
- 名前の案：`m-predict`、`m-calc`（または `m-worksheet`）。決めるのは承認のとき。

## 9. 規格化の答え（2026-10-25）

1. live の集計を部品の中に出す：**よい**。見せると決めた後だけ、数だけ、`ctx.live` から読むだけ、少ないとき（暫定 3 人未満）は出さない、動画・印刷には出さない（§6）。規格化が live.md を書き換える。
2. 入力の欄の中のキー：Studio #69 で実行系が無視する。main で確かめ、部品の入力の欄で試験を足す。
3. スライドをまたいで値を残さない（v1）：**よい**。
4. 発表者の画面から：`deck-cmd` で `{type: "input", key, id, value}`。dev と確かめる。動画では受け付けない。
5. 原稿のト書き：`{note:…}`（読み上げない、字幕に出さない、発表者の画面に出す）。仕様 §8.2 に足す。

作り始めるのは、v1.2.0 が出て、作者が承認してから。仮の名前は `m-predict`、`m-calc`。
