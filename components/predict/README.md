summary: 予想してから答えを開く。選択肢ごとの人数を棒で見せ、答えの段階で正解に枠
steps: 0 問いと選択肢、1 人数の棒、answer-step（既定 2）で答え
purposes: predict
variants: fade, draw
props: answer-step, unit, poll, ticks

「A だと思う人〜」と手を挙げてもらい、先生が −1・＋1 で数える（数を打ち込んでもよい）。一人で学ぶ人は選択肢を押すと自分の予想になる。

子の JSON：`{"question", "choices": [{"label", "tone"?}], "answer": 正解の番号（0 から）, "counts"?: [選択肢ごとの例の人数], "note"?: 答えと出す一言}`

- 選択肢は 2〜6。動画・印刷・最初の表示は `counts`（無ければ 0）。数えた数は段階に入ると `counts` に戻る
- 口述原稿は `counts` の数で書き、数える所は `{note:ここで手を挙げてもらう}` と書く（丸かっこは読み上げられる）
- `poll="p1"`：live の投票の集計を出す

作る人向けの注（dev と確かめること）

- 段階：0 は問い・選択肢・目盛り（地図の段階 0 の地と同じく、文脈は初めから見せる。共通の決まり）。1 で人数の棒と操作、`answer-step` で正解の枠・「✓ 正解」・`note`、ほかの選択肢は棒を薄く、字は `--muted`（4.5:1 以上）。`answer-step="1"` なら棒の後に続けて開く。授業の表示（lecture）では先の棒を 0.45 で見せるが、答えは先に見せない（予想の部品なので。共通の決まりからの外れ）
- 見る人の状態（仕様 §8.4、Studio の約束事 §3）：render が前と違う k で呼ばれたとき・`ctx.reset` のとき・`deck:pos`（`ctx.reset` を渡さない v0.4.x の実行系で、`DECK.go` で同じ段階に入り直したとき）・`beforeprint` で捨てる。`DECK.seek` だけで同じ段階に入り直すときは、`ctx.reset` を渡す実行系でだけ戻る
- 要素のメソッド（Studio が呼ぶ）：`input(choice, count)`（choice は 0 から数える選択肢の番号、count は新しい数で 0〜9999 の整数。それ以外は console.warn して無視。動画では何もしない。返り値なし）。`counts()`：今の数の新しい配列（変えていなければ作者の値）。発表者の画面の `deck-cmd` `{type: "input", …}` から `input()` へ渡すのは Studio の中のこと
- 数が変わったとき（ボタン・欄・キー・`input()`）と、数を変えた後に戻したとき：要素に `CustomEvent("egatari-input", {bubbles: true, detail: {counts}})`。ふつうの描画では出さない
- live：`ctx.live?.poll(poll の値)` → `number[] | null`。配列のときだけ棒に出し（「投票の結果」、操作は隠す）、動画・印刷では出さない。見せてよいか（見せると決めた後、3 人以上）は実行系が決める。集計が変わったら実行系が render を呼び直す
- キー：数の欄と ±1 のボタンで `+` `-` `↑` `↓`（ボタンでは `←` `→` も）。数字のキーは割り当てない（欄の中で打つときだけ）。欄の中のキーはスライドに渡さない（Studio #69 の前でも）。Esc・Enter で欄を出る
- 動画では操作も予想の印も作らない。印刷では `@media print` で隠す
- 自分の予想も段階に入ると消えるので、当たり外れが出るのは答えの段階で押したときだけ（作者に確かめる）
